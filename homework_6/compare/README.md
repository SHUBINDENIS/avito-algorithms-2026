# Compare

Mergesort делит список пополам до отдельных элементов. При слиянии берём меньший из двух первых оставшихся элементов. Так из двух отсортированных половин получается отсортированный список.

Quicksort берёт последний элемент за опорный. После разбиения слева стоят все меньшие, справа – остальные. Опорный уже на своём месте, поэтому остаётся отсортировать обе части. Меньшую сортируем рекурсивно, большую – в том же вызове циклом. Обе сортировки сохраняют вход.

`timed` вызывает функцию между двумя замерами `perf_counter()` и возвращает результат и время в секундах. На один вызов добавляется O(1) времени и памяти.

## Сложность

- **Mergesort:** O(n log n) времени – O(n) работы на каждом из O(log n) уровней. Память O(n) на промежуточные списки, чей размер вдоль ветви убывает вдвое. Стек O(log n).
- **Quicksort:** в среднем O(n log n) на случайной перестановке разных элементов. Разбиения в среднем дают логарифмическое число уровней. В худшем случае O(n²) – размеры идут от n до 1. Память O(n) на копию списка и O(log n) на стек, потому что рекурсивный вызов получает максимум половину диапазона.

## Пример

Вход: `[6, 2, 5, 1, 4, 2, 3]`.

Mergesort делит его на `[6, 2, 5]` и `[1, 4, 2, 3]`. Слияния идут в таком порядке:

```text
[2] + [5] → [2, 5]
[6] + [2, 5] → [2, 5, 6]
[1] + [4] → [1, 4]
[2] + [3] → [2, 3]
[1, 4] + [2, 3] → [1, 2, 3, 4]
[2, 5, 6] + [1, 2, 3, 4] → [1, 2, 2, 3, 4, 5, 6]
```

Quicksort, индексы с нуля и обе границы включены:

| Диапазон | Опорный | Список после разбиения |
|---|---:|---|
| 0–6 | 3 | `[2, 1, 2, 3, 4, 5, 6]` |
| 4–6 | 6 | `[2, 1, 2, 3, 4, 5, 6]` |
| 4–5 | 5 | `[2, 1, 2, 3, 4, 5, 6]` |
| 0–2 | 2 | `[1, 2, 2, 3, 4, 5, 6]` |

## Тесты и замеры

Есть тесты на пустой список, один элемент, отрицательные числа, повторы, разные порядки и сохранение входа. У декоратора отдельно проверяются результат и время с подменой таймера.
