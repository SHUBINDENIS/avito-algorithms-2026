# Задача 3. Merge lists

## Условие

Объединить два отсортированных односвязных списка в один отсортированный список и вернуть его голову. Результат должен состоять из узлов исходных списков.

Реализовать два способа: с фиктивным элементом и без него. Написать тесты.

Пример: `[1, 2, 4]` и `[1, 3, 4]` → `[1, 1, 2, 3, 4, 4]`.

## Идея решения

Сравниваю головы оставшихся частей двух списков и присоединяю меньший узел к хвосту результата. Затем передвигаю указатель в том списке, откуда взят узел. При равенстве беру узел из первого списка.

Голова отсортированного списка — его минимальный оставшийся элемент. Поэтому меньшая из двух голов — минимальный элемент среди всех ещё не взятых. Каждый такой выбор сохраняет сортировку результата и забирает ровно один исходный узел. Когда один список закончится, оставшийся хвост второго уже отсортирован и его можно присоединить целиком.

### С фиктивным элементом

В `merge_with_dummy` создаю узел `dummy` перед будущим результатом. Сначала `tail` указывает на него. Благодаря этому первый узел присоединяется так же, как все остальные: через `tail.next`. Возвращаю `dummy.next`, сам фиктивный узел в ответ не входит. Его значение 0 не участвует в сравнениях, поэтому отрицательные числа тоже обрабатываются правильно.

### Без фиктивного элемента

В `merge_without_dummy` сначала обрабатываю пустые списки. Если оба непустые, выбираю меньшую голову как `head` результата и сдвигаю соответствующий входной указатель. Дальше выполняю тот же цикл слияния.

Обе функции меняют ссылки `next` исходных узлов, а не копируют значения в новые узлы. После вызова исходные списки не сохраняются как независимые цепочки. Входы предполагаются обычными списками без циклов и общих узлов. Для сравнения двух способов нужно создать входные списки заново.

## Сложность

Для обоих способов, где `n` и `m` — длины списков:

- Время — `O(n + m)` в худшем случае: на каждом шаге один указатель сдвигается вперёд, повторных обходов нет. Остаток присоединяется одной операцией.
- Дополнительная память — `O(1)`: используются несколько указателей; в первом способе ещё один фиктивный узел. Узлы результата уже существуют во входных списках. Рекурсии нет.

## Разбор на примере

Возьмём `A: 1 → 2 → 4`, `B: 1 → 3 → 4`. Буква у числа показывает, из какого списка взят узел. В колонке результата показана уже выбранная часть цепочки; ссылки последнего узла на ещё не обработанный остаток не изображены.

| Шаг | Действие | Выбранная часть результата | Осталось A | Осталось B |
|---|---|---|---|---|
| 1 | `1 <= 1`, берём A | `1A` | `2 → 4` | `1 → 3 → 4` |
| 2 | `2 > 1`, берём B | `1A → 1B` | `2 → 4` | `3 → 4` |
| 3 | `2 <= 3`, берём A | `1A → 1B → 2A` | `4` | `3 → 4` |
| 4 | `4 > 3`, берём B | `1A → 1B → 2A → 3B` | `4` | `4` |
| 5 | `4 <= 4`, берём A | `1A → 1B → 2A → 3B → 4A` | пусто | `4` |
| 6 | Присоединяем остаток B | `1A → 1B → 2A → 3B → 4A → 4B` | пусто | — |

С фиктивным узлом до первого шага есть `dummy`, и `tail` указывает на него. Шаг 1 выполняется внутри цикла, результат возвращается через `dummy.next`.

Без фиктивного узла шаг 1 выполняется до цикла: `head` и `tail` становятся равны узлу `1A`. В цикле остаются шаги 2–5, после него присоединяется остаток. Возвращается `head`.

## Тесты

Каждый случай проверяется для обоих способов: пример из условия, пустые списки, по одному узлу, одинаковые значения, отрицательные числа, ноль, разные длины, непересекающиеся диапазоны, чередующиеся значения и длинные списки.

Проверяется не только порядок значений: набор исходных объектов должен сохраниться, каждый узел должен встретиться ровно один раз, циклов быть не должно. Это позволяет заметить решение, которое выдаёт правильные числа, но вместо слияния создаёт копии узлов.
