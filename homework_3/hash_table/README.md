# Задача 3. Хеш-таблица

## Условие

Реализовать хеш-таблицу для хранения пар «ключ — значение». Нужны вставка, поиск и удаление. Для хранения данных разрешён только `list`.

## Устройство

### Хранение данных

Таблица — список бакетов. Каждый бакет — отдельный список пар `[key, value]`.

Индекс бакета вычисляется так:

```python
hash(key) % len(self._buckets)
```

Количество элементов хранится в `_size`, поэтому `len(table)` работает за O(1).

Ключ должен быть хешируемым. Например, подходят числа, строки и кортежи из хешируемых элементов. Список ключом быть не может.

### Разрешение коллизий

Используется метод цепочек. Если разные ключи попали в один бакет, их пары хранятся в одном списке.

При поиске сравниваем ключи внутри нужного бакета. Совпадение хешей само по себе не означает, что ключи одинаковые.

При повторной вставке ключа обновляем значение существующей пары. Размер таблицы не меняется.

Цепочки выбраны из-за простого удаления. При открытой адресации нельзя просто очистить занятую ячейку: поиск другого ключа может остановиться на ней раньше времени. Для удаления там нужна специальная метка tombstone, через которую поиск продолжится.

### Заполнение и расширение

Коэффициент заполнения:

```text
число элементов / число бакетов
```

Если после вставки он становится больше `0.75`, количество бакетов увеличивается вдвое.

Все пары переносятся в новую таблицу. Для каждого ключа индекс вычисляется заново, потому что изменился делитель в операции `%`.

При переносе пары добавляются прямо в новые бакеты. `_size` не меняется: число элементов осталось прежним.

### Удаление

Находим нужный бакет, затем пару с указанным ключом. Удаляем её из списка и уменьшаем `_size`.

Если ключа нет, вызывается `KeyError`. Поиск отсутствующего ключа тоже вызывает `KeyError`.

Автоматическое сжатие не реализовано. После удаления элементов число бакетов сохраняется.

### Поддерживаемые операции

| Операция | Действие |
|---|---|
| `put(key, value)` | Добавить или обновить значение |
| `get(key)` | Получить значение |
| `delete(key)` | Удалить пару |
| `len(table)` | Получить количество элементов |
| `key in table` | Проверить наличие ключа |
| `table[key]` | Получить значение |
| `table[key] = value` | Добавить или обновить значение |
| `del table[key]` | Удалить пару |

Значение `None` можно хранить: наличие ключа определяется по ключу, а не по значению.

## Сложность

Пусть `n` — количество элементов. Оценки предполагают постоянную стоимость вычисления хеша и сравнения ключей.

| Операция | В среднем | В худшем случае |
|---|---|---|
| Вставка | O(1) амортизированно | O(n) |
| Поиск | O(1) | O(n) |
| Удаление | O(1) | O(n) |
| Проверка наличия | O(1) | O(n) |
| Получение размера | O(1) | O(1) |
| Расширение | O(n) | O(n) |

В худшем случае все ключи оказываются в одном бакете. Тогда приходится просматривать цепочку длины `n`.

Расширение стоит O(n), но происходит редко: число бакетов каждый раз удваивается. Поэтому вставка в среднем имеет амортизированную стоимость O(1).

Память — O(n + m), где `m` — число бакетов. После массового удаления `m` может быть значительно больше `n`, поскольку сжатия нет.

## Разбор на примере

Начальная ёмкость — 4. Используем целочисленные ключи `1`, `5`, `2`, `3`. Для этих чисел `hash(key)` равен самому числу.

### До коллизии

После `put(1, "a")`:

```text
0: []
1: [[1, "a"]]
2: []
3: []
```

### После коллизии

Добавляем `put(5, "b")`.

Индексы совпадают:

```text
1 % 4 = 1
5 % 4 = 1
```

Обе пары остаются в одном бакете:

```text
0: []
1: [[1, "a"], [5, "b"]]
2: []
3: []
```

### До расширения

После `put(2, "c")`:

```text
0: []
1: [[1, "a"], [5, "b"]]
2: [[2, "c"]]
3: []
```

Заполнение равно `3 / 4 = 0.75`, поэтому расширение ещё не нужно.

Добавляем `put(3, "d")`. Заполнение становится `4 / 4 = 1`, что больше порога.

### После расширения

Ёмкость увеличивается до 8. Индексы пересчитываются:

```text
1 % 8 = 1
5 % 8 = 5
2 % 8 = 2
3 % 8 = 3
```

Новая таблица:

```text
0: []
1: [[1, "a"]]
2: [[2, "c"]]
3: [[3, "d"]]
4: []
5: [[5, "b"]]
6: []
7: []
```

Размер по-прежнему равен 4. Коллизия ключей `1` и `5` исчезла, заполнение стало `4 / 8 = 0.5`.

Проверяются:

- вставка и чтение, в том числе значения `None`;
- обновление без изменения размера;
- удаление;
- чтение и удаление отсутствующего ключа;
- ключи с одинаковым хешем;
- обновление и удаление внутри цепочки коллизий;
- вставка 1000 элементов с расширением;
- удаление всех элементов и повторная вставка;
- строки, числа, кортежи и `None` как ключи;
- операции через квадратные скобки;
- недопустимая начальная ёмкость;
- 3000 случайных операций в сравнении со встроенным `dict`.
