# Перестановки

## Условие

Вернуть все перестановки массива. Предусмотреть визуализацию рекурсивного стека, используя Tracer.

## Идея

Поиск с возвратом. `path` – уже выбранный префикс, `used[i]` отмечает использованные индексы. Пробуем каждый доступный элемент, рекурсивно дополняем префикс, затем отменяем выбор. При длине n сохраняем копию пути. Локальный `seen` не даёт получить одинаковые перестановки при повторяющихся значениях. Входные значения должны быть хешируемыми; примеры используют целые числа.

Инвариант: `path` содержит выбранные элементы, и ровно их индексы отмечены в `used`. Каждый результат достигается ровно одной ветвью. Отмена выбора восстанавливает состояние для следующей ветви.

## Пример и стек

Для `[0, 1]`:

```text
-> visit([])
  -> visit([0])
    -> visit([0, 1])
    <- visit = [0, 1]
  <- visit = None
  -> visit([1])
    -> visit([1, 0])
    <- visit = [1, 0]
  <- visit = None
<- visit = None
```

Результат: `[[0, 1], [1, 0]]`. Для пустого массива одна пустая перестановка: `[[]]`.

```python
permutations([1, 2, 3], trace=True)
```

`trace=False` по умолчанию, чтобы обычный вызов возвращал результат без большого лога. Режим `trace=True` оборачивает рекурсивную функцию декоратором из соседней задачи. Запуск `solution.py` включает трассировку.

## Сложность

Для n разных элементов O(n × n!) времени и O(n × n!) памяти результата. Вспомогательная память O(n²) в худшем случае: помимо пути, used и стека, в каждом активном кадре есть собственный `seen`. Это верхняя оценка для принятой поддержки повторов. Трассировка добавляет время, пропорциональное объёму вывода; уже на больших n её лучше выключать.
